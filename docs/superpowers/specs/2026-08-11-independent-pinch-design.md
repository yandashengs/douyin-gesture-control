# 独立捏合音量识别设计

## 根因

现有捏合识别同时依赖当前帧姿势和投票后的稳定姿势。真实拇指—食指收缩/张开经常被静态分类为 `POINT`，且动作在静态投票与 200ms 捏合确认完成前已经结束。第一次确认状态又只允许 `OTHER` 发出事件，导致 `POINT` 路径被吞掉，随后触发指向保持。

## 设计

新增 `PinchGestureDetector`，只消费 `HandFrame.pinchRatio` 和时间戳，以滞回状态机识别 `OPEN -> CLOSED` 与 `CLOSED -> OPEN`。它不依赖 `HandPose` 或 `stablePose`，初始状态只建立基线、不发事件；终态连续确认 120ms 后发出一次事件。中间区间保留原状态，短暂丢手后重置。

`GestureDetector` 保留原静态分类、投票和保持逻辑，只把现有 `pinchEvent` 替换为独立检测器。捏合检测器处于候选转换期间时暂缓 `PointHold`，防止指向事件抢先；普通静止 POINT 没有比例跨阈值，仍按原时间触发。

## 不修改范围

- 不修改 `HandPoseClassifier` 及 POINT、OK、V、FIST、OPEN_PALM 判定。
- 不修改掌心滑动状态机。
- 不修改手势映射、音量执行、点赞、评论或暂停逻辑。
- 保留当前闭合阈值 `0.30` 和张开阈值 `0.55`，实机日志证明两端数据能跨越它们。

## 验证

- 全程被分类为 POINT 的闭合到张开、张开到闭合均产生正确事件。
- 初始 POINT 不产生音量事件。
- 静止 POINT 仍产生一次 `PointHold`。
- 捏合候选期间不产生 `PointHold`。
- 现有全部静态手势、滑动和映射测试保持通过。
