# 掌心轨迹滑动识别设计

## 背景与根因

实机日志显示，用户张开手掌移动期间，MediaPipe 能持续输出手部关键点，但静态分类结果在 `FIST`、`V_SIGN`、`OTHER` 和 `NONE` 之间变化，从未稳定成为 `OPEN_PALM`。现有滑动检测只采集被标记为 `OPEN_PALM` 的帧，因此没有形成可判定的轨迹。

动态移动会带来手指弯曲、运动模糊、透视变化和部分遮挡。把动态滑动依赖于严格的静态姿势分类，是本次失效的根因。继续降低静态分类阈值会同时增加点赞、评论等静态手势误判，不能从架构上解决问题。

## 范围与成功标准

本阶段只解决张开整只手掌上下移动时：

- 上滑和下滑能稳定触发；
- 短暂静态姿势误分类或少量关键点丢帧不会中断轨迹；
- 手掌远近、画面分辨率变化不改变基本灵敏度；
- 静止抖动、横向移动和非张掌姿势不触发滑动；
- 不增加音量、点赞、评论的误触。

点赞和评论的跨机型屏幕定位不在本阶段修改，作为下一阶段单独设计与验证。

## 方案

### 1. 从静态分类中提取连续特征

新增不带业务事件的手部运动特征：

- 掌心中心：手腕与食指、中指、无名指、小指四个 MCP 指根点的加权中心；
- 掌宽：食指 MCP 到小指 MCP 的距离；
- 张掌评分：四根手指中满足伸展特征的数量，并结合指尖到掌心的距离；
- 原始静态姿势：继续提供给现有点赞、评论、暂停等逻辑，但不再决定是否采集运动轨迹。

掌心中心比手腕更接近整只手的视觉中心，手腕转动时漂移更小。掌宽作为尺度基准，使同一挥动在手靠近或远离摄像头时具有相近判定结果。

### 2. 独立掌心运动状态机

滑动检测维护以下状态：

1. `IDLE`：等待检测到满足软张掌条件的手；
2. `ARMED`：连续短时间满足软张掌条件，记录掌心起点和掌宽；
3. `TRACKING`：累计最近窗口中的归一化纵向轨迹；
4. `FIRED`：已触发，等待手掌静止、离开或反向复位，防止一次挥动重复触发。

软张掌条件不要求分类结果为 `OPEN_PALM`，只要求至少三根手指具有足够的伸展证据。轨迹开始后允许短时间内评分降低或关键点丢失；超过容错时间才取消。

### 3. 滑动判定

轨迹使用 `位移 / 掌宽` 归一化，满足全部条件才触发：

- 时间位于合理窗口内，过滤瞬时跳点和过慢漂移；
- 纵向累计位移超过阈值；
- 横向位移相对较小；
- 大部分有效步长方向一致；
- 不存在缺少后续支撑的单帧大跳变；
- 轨迹期间有足够比例的张掌证据。

上下方向以相机图像坐标为准：掌心 `y` 减小为上挥，增大为下挥。最终仍映射到现有 `SwipeUp` 和 `SwipeDown` 事件，不修改动作执行层。

### 4. 静态手势隔离

现有静态姿势投票继续用于拳头后张开、V 字保持和手掌保持。动态滑动触发优先级高于静态保持；滑动进入跟踪状态后，暂停手掌保持计时，避免一次挥动同时触发暂停。

音量捏合继续只在独立、稳定的捏合上下文内工作，不读取掌心滑动状态，也不因滑动过程中拇指和食指距离变化而触发。

## 诊断与实机校准

诊断日志记录每条候选轨迹的起止时间、归一化 `dx/dy`、方向一致性、张掌帧比例和取消原因。只记录聚合数值，不保存摄像头图像。

单元测试通过后安装到当前小米 2211133C 实机。实测时分别完成上挥、下挥、静止张掌、横移、V 字和握拳；以日志确认识别层是否发出正确事件，再确认无障碍动作是否执行。若需要调参，每次只调整一个有实机数据支持的阈值。

## 测试策略

先添加失败测试，再实现生产代码。测试至少包括：

- 静态分类持续为 `OTHER`，但软张掌特征成立时可上滑；
- 轨迹中短暂出现 `FIST`、`V_SIGN` 或两到三帧无手仍可完成；
- 相同相对位移在大小不同的手掌上均触发；
- 静止抖动、横移、单帧跳点和拳头移动不触发；
- 一次挥动只触发一次，复位后才能再次触发；
- 滑动不触发手掌保持或音量事件；
- 现有静态手势回归测试保持通过。

## 非目标

- 不训练或引入新的神经网络模型；
- 不保存或上传摄像头帧；
- 不在本阶段改变点赞、评论等屏幕动作坐标；
- 不提供用户手动阈值面板，优先确保默认配置可用。
