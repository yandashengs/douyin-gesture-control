# 七种手势识别准确性设计

## 背景与证据

摄像头、MediaPipe、无障碍动作链路已经恢复，实机在 30 秒内持续处理 690 帧，动作也能成功控制抖音。继续测试暴露出识别层问题：同一轮摆手期间交替出现“指向保持”“握拳张开”“捏合张开”等事件，并存在摆出手势却无响应的情况。

现有实现存在四个直接原因：

- MediaPipe 使用 `RunningMode.IMAGE`，每帧独立检测，无法利用视频跟踪稳定关键点。
- 静态分类只比较指尖和关节到手腕的距离，缺乏关节角度、掌长归一化和跨帧确认。
- 挥动与捏合都比较相邻两帧；正常慢动作难以超过阈值，关键点跳动却可能误触发。
- 保持手势会按冷却时间重复触发；一帧误判为握拳后恢复张掌，也会误触发“握拳张开”。

## 目标

保留并提高以下七种默认手势的可用性：

1. 张掌上挥。
2. 张掌下挥。
3. 稳定握拳后张开。
4. V 字保持。
5. 张掌保持。
6. 拇指食指捏合。
7. 拇指食指张开。

同时保留三个可配置静态姿势：指向、OK、摇滚。它们默认可映射为禁用，但检测器必须能够稳定区分。

成功标准：

- 单个噪声帧不能触发任何动作。
- 稳定姿势必须经过连续时间窗口确认。
- 一次姿势保持只触发一次；离开后重新摆出才能再次触发。
- 挥动使用累计轨迹识别，正常速度动作可触发，静止抖动不触发。
- 捏合仅在开闭状态发生完整穿越时触发，张掌或普通移动不触发音量。
- 握拳张开要求两个姿势分别稳定，不允许一帧握拳误判触发点赞。
- 同一帧最多产生一个事件，并按明确优先级仲裁。

## 总体方案

继续使用现有 `hand_landmarker.task`，不增加 Gesture Recognizer 模型。数据流调整为：

```text
CameraX 1280x720 RGBA
    -> MediaPipe VIDEO 跟踪
    -> 关键点特征提取
    -> 单帧候选姿势
    -> 时间稳定器
    -> 动态轨迹/状态穿越检测
    -> 事件优先级仲裁
    -> GestureEvent
```

## MediaPipe 与摄像头

- ImageAnalysis 请求 1280×720，保持 `STRATEGY_KEEP_ONLY_LATEST` 和 RGBA 输出。
- HandLandmarker 切换为 `RunningMode.VIDEO`。
- 使用 CameraX 图像时间戳转换成毫秒并调用 `detectForVideo`；输入时间戳必须严格单调递增。
- 检测、存在与跟踪置信度初始值分别设为 0.4、0.4、0.5。前两项略低以改善远距离召回率，后续稳定器负责抑制噪声。
- 仍只跟踪一只手。

## 可测试的数据边界

新增纯 Kotlin 数据类型 `HandPoint(x, y, z)`，HandLandmarkerWrapper 负责把 MediaPipe NormalizedLandmark 转换成该类型。GestureDetector 不再依赖 MediaPipe 类，使几何与时序测试能在 JVM 上直接运行。

时间由调用方传入单调递增的毫秒值；测试使用手工时间戳，不依赖系统时钟。

## 单帧姿势分类

### 手指伸展

食指、中指、无名指和小指分别使用 MCP-PIP-DIP-TIP 几何：

- PIP 关节夹角达到伸展阈值；
- DIP 关节夹角达到伸展阈值；
- 指尖到手腕距离相对掌长达到最小比例。

三个条件共同成立才算伸直，减少手掌旋转、手指弯曲和透视造成的串类。掌长使用手腕到中指 MCP 的距离，所有距离阈值按掌长归一化。

### 姿势规则与顺序

优先识别特征最独特的姿势：

1. OK：拇指尖与食指尖距离小于闭合阈值，且中指、无名指、小指伸直。
2. V 字：食指和中指伸直，无名指和小指弯曲。
3. 摇滚：食指和小指伸直，中指和无名指弯曲。
4. 指向：只有食指伸直。
5. 张掌：四指全部伸直。
6. 握拳：四指全部弯曲，且四个指尖平均距离掌心足够小。
7. 其他。

拇指伸展不参与张掌、握拳、V 字和指向的主位掩码，避免左右手与镜像方向造成差异；拇指只参与捏合/OK 距离。

## 时间稳定器

- 保存最近 400ms 的候选姿势。
- 至少包含 5 个有效手部帧。
- 同一候选占有效帧 70% 以上，且连续保持至少 180ms，才切换为稳定姿势。
- 无手超过 250ms 后清空稳定姿势、轨迹和未完成的组合动作。
- 每次稳定姿势进入时生成 episode；保持事件在一个 episode 内最多触发一次。

## 各手势时序

### 上挥/下挥

- 只采集稳定或高置信候选张掌的手腕位置。
- 保留最近 650ms 轨迹。
- 起点到终点垂直位移至少为画面高度的 14%。
- 水平漂移不得超过 18%。
- 至少 70% 的相邻垂直步进方向与最终方向一致。
- 轨迹跨度至少 180ms，避免关键点单帧跳变。
- 触发后锁存，直到移动速度降低并重新稳定张掌，或手离开画面。

### 握拳张开

- 稳定握拳 episode 成立后记录时间。
- 之后 900ms 内进入稳定张掌才触发。
- 中途丢手超过 250ms、进入其他稳定姿势或超时均取消。
- 触发后清除组合状态，必须重新稳定握拳才能再次触发。

### 保持姿势

- V 字稳定保持 800ms 后触发一次。
- 张掌稳定且低速保持 1200ms 后触发一次；存在有效挥动轨迹时不触发。
- 指向、OK、摇滚稳定保持 700ms 后各触发一次。
- 离开对应稳定姿势后才解除一次性锁存。

### 捏合开合

- 使用拇指尖到食指尖距离除以掌长得到 pinchRatio。
- `pinchRatio <= 0.32` 进入 CLOSED。
- `pinchRatio >= 0.58` 进入 OPEN。
- 中间区域保持原状态，形成迟滞，避免阈值附近抖动。
- 初次看到手只初始化状态，不触发事件。
- OPEN→CLOSED 触发捏合收缩；CLOSED→OPEN 触发捏合张开。
- 状态切换要求目标区域连续稳定至少 120ms。
- OK 稳定姿势期间不触发音量捏合事件。

## 事件仲裁优先级

每帧最多输出一个事件，优先级从高到低：

1. 上挥/下挥。
2. 握拳张开。
3. 捏合收缩/张开。
4. V 字、指向、OK、摇滚保持。
5. 张掌保持。

任何事件触发后进入 650ms 全局冷却；状态仍更新，但不能输出新事件。

## 诊断日志

- 候选姿势变化只在变化时记录，不逐帧刷日志。
- 稳定姿势进入/离开记录姿势、投票比例和稳定时长。
- 动态事件记录位移、轨迹时长、方向一致率或 pinchRatio 状态穿越。
- 每 30 帧继续记录总帧数和检测到手的帧数。

## 测试

纯 JVM 测试覆盖：

- 十种静态姿势的代表性关键点分类。
- 单帧错误候选不会切换稳定姿势。
- 70% 投票与最少帧数边界。
- 慢速上挥和下挥成功；静止抖动、水平移动、单帧跳变失败。
- 稳定握拳后稳定张掌成功；单帧握拳、超时和中途丢手失败。
- 捏合迟滞、初始状态不触发、OK 不触发音量。
- 每个保持 episode 只触发一次，离开再进入可再次触发。
- 同一时间满足多个条件时遵守事件优先级。

实机验证按固定顺序逐项执行七个默认手势，并记录“预期事件/实际事件/是否漏识别”。如果同一手势连续十次测试仍有两次以上误判或四次以上漏判，再基于诊断数据只调整对应特征或阈值，不混改多个变量。

## 非目标与限制

- 不训练个性化模型。
- 不增加云端识别或上传摄像头画面。
- 不承诺在严重逆光、手完全离开画面、距离过远导致手部像素不足时识别。
- 不自动修改 MIUI 后台、自启动或无障碍系统设置。
